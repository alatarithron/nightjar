# Thunderbird custom-property reference

Generated by `bin/dump-tb-reference.sh` from `/usr/lib/thunderbird/omni.ja` (Thunderbird 153.0).
Do not edit by hand. Re-run after upgrading Thunderbird.

Only properties listed here exist. Overriding anything else in
`src/` is a silent no-op. The list covers every custom property declared
under `chrome://messenger/skin/`, `chrome://messenger/content/` and
`chrome://calendar/skin/`, grouped by how good an override surface each
one is.

## Folder colors

Declared on `:root` in `chrome://messenger/skin/folderColors.css` and consumed
by the folder pane as `--icon-color`, which feeds both context tones.

These are the **default** colors only. A color the user picks for a folder, and
a tag color, are applied by `about3Pane.js` as an inline style on the row
(`row.icon.style.setProperty("--icon-color", …)`), and an inline style wins over
any stylesheet. The inbox additionally prefers `--account-color` when set.
Overriding the tokens below therefore restyles the defaults without taking the
user's choice away.

```css
--folder-color-archive
--folder-color-draft
--folder-color-folder
```

## Color primitives

Declared in `chrome://messenger/skin/colors.css`. Two different kinds of
thing share this file, and they are not interchangeable.

The **raw scale** — `--color-blue-50`, `--color-gray-70`, `--color-ink-40` —
is not overridden. Thunderbird's components pick from it for meaning, so
repainting a rung changes things that were never about the theme, and the
semantic layer that consumes it is the right place to intervene.

The **roles** — `--color-primary-*`, `--color-surface-*` — are overridden.
They behave like the semantic tokens in `variables.css` and merely live
here: the primary action color and the surface ramp, read across the
account hub, account settings, downloads, import and the calendar dialogs.

it is wired to anything. Before trading a working selector for a token,

## Selector targets that exist

The element ids and custom-element names `src/` selects on, filtered down
to the ones Thunderbird actually has. Unlike every section above this one is
**not** exhaustive: Thunderbird defines around eight thousand ids and listing
them all would bury the rest of this file.

It is still a real check, because the filter runs against `omni.ja`, not
against `src/`. A name Nightjar uses and Thunderbird does not have is simply
never emitted, no matter how many times this script is re-run, so
`bin/check.sh` can read an absence as a failure.

Selectors are the fallback when no token expresses a change, and they are
the part of the theme an upgrade breaks first. This section does not prove
a selector *matches* — an id can exist at a different depth than the
combinator assumes, which is a failure only a running Thunderbird shows.
